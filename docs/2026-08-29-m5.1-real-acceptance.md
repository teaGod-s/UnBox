# M5.1 真实爬虫验收步骤（本地）

日期：2026-08-29
状态：本地手动执行，**真实地址/脚本不进 git**

用真实 FongMi JS0（或 drpy2）爬虫跑通 M5.1 的
`加载 → 分类 → 列表 → 搜索 → 详情 → 播放`，回答一个关键问题：

> 文本级的 `async/await` 剥离（`normalizeModuleSource`）对真实爬虫够不够用，
> 还是要升级到 goja 原生 Promise 处理（方案 B）？

## 合规红线

- 真实 `.js` 地址 / 脚本内容 **只经环境变量传入**，绝不写进代码、注释、commit。
- 验收完跑 `git status` 确认没有把地址写进任何文件。
- 若 Load 失败，验收测试会把剥离后的源码写到 `/tmp/unbox-normalized.js`，
  里面含真实地址，看完记得删：`rm -f /tmp/unbox-normalized.js`。

## 准备

1. 一个真实 FongMi JS0 爬虫：要么是 `.js` 下载地址，要么是已下载到本地的 `.js` 文件。
2. 一个可搜索的关键词（该站能搜到东西的词，如「斗罗」）。
3. 项目根目录（`go.mod` 所在处）执行下面的命令。

## 运行

**方式 A：远程地址**

```bash
UNBOX_REAL_JS_URL='<真实 .js 地址>' \
UNBOX_REAL_SEARCH='<关键词>' \
go test ./internal/crawler -run TestRealCrawlerAcceptance -v
```

**方式 B：本地文件**

```bash
UNBOX_REAL_JS_PATH='/absolute/path/to/spider.js' \
UNBOX_REAL_SEARCH='<关键词>' \
go test ./internal/crawler -run TestRealCrawlerAcceptance -v
```

`-v` 会把每一步的结果打出来（分类、列表前 3、搜索前 3、详情、播放地址）。

> 提示：把地址写进 shell 历史可能留下记录。介意的话用
> `read -s` 或先 `export` 在子 shell 里跑，验收完 `history -c` 清历史。

## 观察点与判定树

对照 `-v` 输出：

| 阶段 | 现象 | 判定 |
|------|------|------|
| 加载 | `加载爬虫失败 ... SyntaxError / await is not defined` | 🔴 **文本剥离不够**：脚本里有 `await\n`、async 箭头函数、字符串含 "await" 或 `export` 变体超出当前正则。看 `/tmp/unbox-normalized.js` 定位，然后升级 goja 原生 Promise（方案 B） |
| 加载 | 通过，`脚本形态` 那行打印 | ✅ 语法层 OK，继续往下看 |
| 分类 | `VodClasses 失败` 或空 | 🟡 该爬虫不是 `home()`/`rule.class_name` 形态，记录实际返回值形状 |
| 列表/搜索/详情 | 返回格式错误 / 空 | 🟡 drpy/FongMi 返回语义差异（spec §12 风险 2），按实际 `{...}` 形状补 envelope 解析（`template.go` 的 `callVods`/`exportDetail`） |
| 播放 | `VodPlay 失败` | 🟡 懒加载播放地址差异（spec §12 风险 4），校准 `play`/`playContent` 返回形状 |
| 全链路 | 每一步都有真实数据 | ✅ **M5.1 验收通过**，文本剥离够用，无需升级 |

## 结论落点

- **若只在「加载」阶段挂**：说明是 async/await 剥离问题 → 走方案 B（goja 原生
  Promise / eventloop），这是唯一需要动 `crawler.go` 核心的情况。
- **若加载通过、只在某个动作的返回形状挂**：说明剥离没问题，是「返回语义」没对齐
  → 只需改 `template.go` 的 envelope 解析，工作量小。
- **若全绿**：收工，`rm -f /tmp/unbox-normalized.js`。
