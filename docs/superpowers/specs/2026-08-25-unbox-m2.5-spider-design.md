# Unbox M2.5 — JS 爬虫站点（客户端模式）设计

> 状态：已实现（M2.5 完成）。

> ⚠️ **已过时提醒**：本稿的 drpy 客户端 Provider 实际落在
> `internal/provider/tvbox/drpy.go`（非 `internal/provider/drpy`）；本稿排除的
> 「`.js` 直接文件源 / 内嵌 JS 引擎」已在 M5.1/M5.3 落地（goja），详见
> `2026-08-29-unbox-m5-js-engine-design.md`。

## 目标

支持 TVBox 订阅里 `type=3`（爬虫）站点中、`api` 为 `http` 前缀的那一类——即指向
一个 **drpy2 / drpyS 爬虫服务**的站点。Unbox 作为 HTTP **客户端**调该服务的
REST API，把返回的 `vod_*` JSON 复用 M2 的解析逻辑，产出与 CMS 站点一致的
`provider.Page` / `provider.Media`，从而在「点播」面板里无缝出现。

**不在本期范围**：`.js` 直接文件源（需内嵌 JS 引擎，另立里程碑）、`.py`（hipy，
`Classify` 已判 `SupportNo`）、`csp_`（JAR，`SupportNo`）。

## 背景结论（已调研，2026-08-25）

- hipy 实为 **Python** 引擎（`.py` 源），不是 JS；JS 源对应 **drpy2（dr_py2，旧
  Python 框架）/ drpyS（drpy-node，新 Node 框架）**。
- 两个框架的**返回格式都是 `vod_*` 字段**（`vod_id`/`vod_name`/`vod_pic`/
  `vod_play_from`/`vod_play_url`/`vod_content`…），与 M2 的 CMS 协议同构 → 解析
  层直接复用。
- 现 `internal/config/classify.go` 已把 type=3 分四类：`csp_`(jar/No)、`.js`
  (js/Yes)、`.py`(python/No)、`http`(http/**Maybe**)。本期把 `http` 从 Maybe 落到
  Yes，并在收集站点时为其构建 spider Provider。

## 架构

新增一个包 `internal/provider/drpy`，实现 `provider.Provider` 接口，对每个
type=3 `http` 站点创建一个实例。数据流与 tvbox 完全平行：

```
ShellService.ImportSubscription
  └─ collectVodSites(cfgs)          // 现仅 type=1；扩展为 type=1 + type=3 http
       ├─ tvbox.New(site)           // CMS
       └─ drpy.New(site)            // 爬虫客户端（本期新增）
drpy.Provider
  ├─ Home()    → GET {api}/api/homeVod            → []Section（分类）
  ├─ Browse()  → GET {api}/api/category?tid&pg   → Page（列表）
  ├─ Search()  → GET {api}/api/searchContent?key → []Item
  ├─ Detail()  → GET {api}/api/detailContent?ids → Media（剧集）
  └─ Resolve() → GET {api}/api/playerContent?flag&id → Stream（播放 URL）
```

`drpy.Provider` 复用 `tvbox` 的 `cmsVideo`/`cmsResp` 结构与 `toItems`/剧集解析
（拆分剧集、epID 编码逻辑与 CMS 完全一致）。epID 沿用 `vodID/sourceIdx/epIdx`。

## API 契约（canonical dr_py2，drpyS 略有差异）

| 方法 | 端点 | 参数 | 返回 |
|------|------|------|------|
| 首页/分类 | `GET {api}/api/homeVod` | — | `{class:[{type_id,type_name}], list:[vod_*]}` |
| 分类列表 | `GET {api}/api/category` | `tid`, `pg` | `{list:[vod_*], page, pagecount}` |
| 搜索 | `GET {api}/api/searchContent` | `key`（drpyS 或 `wd`） | `{list:[vod_*]}` |
| 详情 | `GET {api}/api/detailContent` | `ids` | `{list:[{vod_*... vod_play_from, vod_play_url}]}` |
| 播放 | `GET {api}/api/playerContent` | `flag`, `id` | `{url, header, parse, jx}` |

> ⚠️ **契约待实测钉死**：dr_py2 与 drpyS 在端点路径（是否带 `/api`）、参数名
> （`key`/`wd`、`ids`/`vod_url`）、返回信封（详情是 `{list:[...]}` 单元素数组还是
> 裸对象）上有差异。**实现 Task 1 必须先用真实实例抓包确认**，再据此写 fixture
> 与解析。分类派生：若无独立分类端点，用列表响应的 `class` 数组（`type_id`/
> `type_name`），同 M2 CMS 的做法。

## 播放解析

`playerContent` 返回 `{url, header:{Referer/User-Agent...}, parse}`：
- `parse=0`：`url` 即最终播放地址，`header` 直接作为 Stream.Headers。
- `parse=1`：`url` 是「解析接口」地址，需套用目标站解析（本期仅透传 `url` 并保留
  `parse=1` 标记，让 mpv 直接加载；若不可播，属后续「解析接口」专项）。

## 配置分类改动

`Classify` 中 type=3 `http` 分支：`SupportMaybe` → `SupportYes`（kind 保持 `"http"`）。
`collectVodSites` 增加对 `site.Type == SiteTypeSpider && strings.HasPrefix(site.API, "http")`
的分支 → `drpy.New(site)`。

## 前端

无需新 UI：drpy 站点与 CMS 站点一样出现在「点播」来源下拉里（`Sources()` 的
`Kind=="vod"` 已通用）。海报、剧集、播放逻辑全部复用。

## 已排除

- `.js` 直接文件源（需内嵌 JS 引擎 goja/node，工作量大、兼容性风险高）→ 独立里程碑。
- `.py`（hipy，Python）→ 不支持（桌面端无 Python 运行时）。
- `csp_`（JAR）→ 不支持。
